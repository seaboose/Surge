## Candidate hypothesis (freeze after calibration)

For eligible server walking intervals, measured displacement should be at most
600 cm/s × elapsed simulation time + 10 cm. An authority-side cap change to
1200 cm/s on a long straight route should produce Review evidence after
acceleration. This models a controlled server configuration/behavior violation,
not a successful remote-client cheat or native-memory-integrity detector.

Before held-out captures, record source/build hashes, UE version, toolchain,
map and navmesh settings, host hardware, policy/adapter hashes, and build logs.
Freeze the policy and routes after development trials. Keep all trials including
failures; do not retune on the held-out set and report it as independent.

## Run matrix

Use at least three fresh sessions per condition, bounded to 60 seconds each.
Capture all configured players. Record planned order and routes before running;
vary condition order between repetitions. A trusted operator keeps an external
action log with capture GUID, action time, requested action, observed cap state
and route. That log and evaluation labels must never enter adapter/Surge input.

| Condition | Action | Expected interpretation |
|---|---|---|
| Nominal | Straight run at 600 | No finding after valid sampling |
| Navigation | Obstacle detour, rapid redirects, arrival, S stop | No finding; report stalls separately |
| Transport | Repeat nominal with latency/loss simulation | Commands/visuals delayed; no displacement finding expected |
| Hitch | Induce documented server pause >0.5 simulation seconds between samples | Unknown for unsupported interval, not a speed finding |
| Invalid behavior | Local listen-server operator: `LabSetSpeed 1200`, then long straight route | Evidence-based Review on eligible excessive-displacement intervals |
| Restoration | `LabSetSpeed 600`, allow braking/settling, then repeat route | No finding once speed settles |
| Authority control | Attempt `LabSetSpeed 1200` on remote client | No cap change and no induced finding |

The speed command is an explicit non-Shipping host-console control, not a client
RPC. No third-party process or security tool is touched. If the command/path
does not execute, report that failed trial; never inject a verdict to compensate.
If latency or a hitch produces a finding, preserve the evidence and investigate
the cause. Passing controls is a gate, not an assumption.

World time can clamp or pause during an editor/OS stall. Inspect adjacent source
sample elapsed_s values before calling an interval a sampling hitch; v2 walking
eligibility ends at 150 ms. A wall-clock pause alone does not establish a server
simulation-time gap. Paused simulation provides no wall-clock coverage guarantee.

## Evidence and report

Preserve raw captures, server logs, external action logs, derived input, exact
policy, Surge case exports, screenshots and SHA-256 hashes in a new local run
folder. Do not overwrite earlier attempts. Independently label held-out intervals
using the action/state record without looking at Surge verdicts. Exclude and
explain acceleration/transition ambiguity before scoring; retain Unknown and
rejected inputs as coverage outcomes, never count them as clean detections.

For each run report row count, elapsed coverage, unknown/rejected intervals,
review intervals, control failures, and time to first Review after confirmed
behavior change. Give confusion counts and sample sizes on independently labeled
eligible intervals, plus per-run outcomes (adjacent intervals are correlated).
Report threshold selection, false positives, misses, route/corner blind spots,
label uncertainty, failed trials and one-host limitations. Do not generalize to
real cheat detection accuracy or Riot's security systems.
