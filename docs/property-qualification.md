# Bounded Python property qualification

Acceptance contract, defined before execution. Run `python -B scripts/qualify.py --properties` (optionally also `--asan`). This optional profile installs pinned Hypothesis dependencies into the checkout environment and tests only synthetic, in-memory records. No native process, modified binary, external application or network target is exercised by the property checks.

1. Manifest validation agrees with a separate byte-occupancy model on generated complete partitions. Each generated layout also checks a hole, overlap, incorrect total, boolean dimension and unsupported descriptor version; all must be rejected. Generated bounds: 2–16 ranges, 1–64 bytes per range, 1–8 excluded bytes after each range.
2. Stream ordering accepts histories built from an independent list of delivered and lost sample slots. Every generated history also checks duplicate/reversed sequence, unexplained sequence gap, decreasing loss count and backwards time rejection. Bounds: 2–16 ranges, 1–8 delivered samples, 0–3 omitted slots between deliveries, increasing elapsed time in steps of 1–500 ms.
3. JSON and JSONL replay agree with explicit expected verdict counts for clean, changed and unavailable approved observations, including Unknown health when samples are dropped. Both encodings must reject a changed process identity and reversed sample order. Every generated history exercises all three observation modes; histories contain at least two samples so ordering checks are meaningful.
4. Each property executes 64 generated examples per seed, for seeds 20261023 and 17, twice. Both passes must have identical input counts and SHA-256 fingerprints. At least 768 property evaluations must complete, with no filtering, skips, suppressed health checks or unexpected exceptions. These counts are evaluations, not unique inputs or code coverage. Failure shrinking may add executions; a failing run cannot qualify.
5. Each Hypothesis example has a 2-second deadline; the property command has a 300-second outer timeout, the existing 20 MiB log cap and overall 30-minute qualification limit. Missing dependencies, incomplete/malformed summaries, short runs, fingerprint mismatches and timeouts fail qualification. Reports retain the package version, seeds, counts, fingerprints and individual step status.

These are a bounded contract-testing subset, not the original T1/T2/T3 campaign. They do not cover native parser fuzzing, all malformed schema fields, production retention limits, independent approval/verdict truth tables for every state, long-duration behavior, coverage-guided reachability, or held-back variants. Local evidence is not attestation. Existing deterministic regressions remain authoritative compatibility checks.

Hypothesis generation and shrinking follow its [API documentation](https://hypothesis.readthedocs.io/en/latest/reference/api.html). A fixed seed and pinned dependencies support same-environment repeatability, not guaranteed identical inputs across different Python/Hypothesis versions.
